# DECISION: форк SoundCraft — статус и триггеры

**Статус: ОВЕРЛЕЙ (форк не активирован).** Наш способ потребления SoundCraft —
upstream + patch-файлы + автосборка (ZCode-плагин собран именно так:
v0.5.0 + `002-workspace-automation.patch`).

**Вариант форка, если сработает триггер: только SoundCraft.**
Основание: MIT/Apache-2.0 (свобода монетизации, включая закрытые AI-фичи
позже), Rust (наша философия), MCP-нативность (наша шина уже в нём),
доказанный пайплайн. Альтернативные базы **отклонены** с основаниями:

| База | Причина отказа |
|---|---|
| Ardour | GPLv2+ (монетизация только донаты/платные бинари), C++ против философии. Роль: адаптер-цель Wave 2 |
| Zrythm | AGPLv3+ — форк наследует AGPL; автор продаёт коммерческие лицензии, наша модель другая |
| LMMS | GPLv2+, паттерновая парадигма (не записывающая DAW) — не наш shape |
| MAGDA | GPLv3 + JUCE/Tracktion; нет CLAP. Роль: референс AI-интеграции (доказывает: соло+AI-DAW возможно) |
| С нуля | 3–5 лет до pre-alpha уровня SoundCraft; допустимо позже как scoped loop-station-эксперимент |

## Триггеры форка (любой из них → пересмотр решения)

**T1. Апстрим мёртв.** Нет коммитов и ответов мейнтейнера **> 6 месяцев**.
Проверка: ежеквартально, фиксировать дату проверки и HEAD апстрима.

**T2. Фича отвергнута.** Наш PR/issue закрыт как wontfix/rejected, и фича
блокирует пользователей L2T (прецеденты уже в очереди: #1701 key-signature,
#1702 import-tempo opt-in).

**T3. Структурное расхождение.** Нужна возможность, которая не ложится в
апстрим-архитектуру: например, рендер-движок AI-аранжировки, интегрированный
с midi-gen на уровне планирования тактов, или свой AI-панельный UI как часть
основного окна.

## Процедура

1. Триггер фиксируется issue в l2t-copilot с evidence (лог, ссылки, даты).
2. Обсуждение в этом файле (добавляется секция «Обсуждение»).
3. Решение: форк / продолжить оверлей / изменить апстрим-стратегию.
4. Форк ≠ отрыв: первые месяцы форка продолжаем выборочный rebase на
   апстрим, если он жив (багфиксы безопасности и критичных путей).

## История решений

- **2026-11-22** — решение основано. Статус: оверлей. Основание:
  дифференциация L2T — AI-слой, не движок; SoundCraft сам развивает
  MCP-нативность (форк дублировал бы апстрим-работу); оверлей даёт скорость
  без merge-hell. Wave 2 переразмечена: Ableton (shelved, OS-mismatch) →
  Ardour/REAPER через DawBackend (docs/dawbackend-spec.md).

**ОБНОВЛЕНИЕ 2026-11-22 (ревью-тур №3): модель потребления SoundCraft эволюционирует.** Разведка №7 (docs/oss-recon-engines.md, ✅ APPROVED Папой): апстрим v0.20.1 имеет standalone headless-стек (soundcraft-cli mcp — нативный MCP на stdio, мультикорневая workspace-песочница, headless-bounce). l2t-core переключается на `soundcraft-cli mcp` (спайк Кодера в работе, bинарь пиннится в ~/bin, паттерн audio-analyzer). РЫНОК ПРОВЕРЕН: permissive DAW-сессионного движка, кроме SoundCraft и Tracktion (GPL/commercial-стена), не существует — миграция не оправдана. **T1-триггер расширен: «деградация soundcraft-cli» также активирует пересмотр** (вместе с fork-вопросом). ZCode-плагин сохраняет роль UI-интеграции ZCode-сессий. audio-analyzer-rs: апстрим мёртв 8+ мес (T1-факт) — решение Папы: остаёмся на pinned-бинарях (работают), roadmap-патч sections.rs в бэклоге.

**РАТИФИКАЦИЯ 2026-11-22 (владелец, после спайка Кодера):**
1. **Движок: SoundCraft v0.20.1 standalone CLI/MCP — УТВЕРЖДЁН** (Исход 3). l2t-core переключается на `soundcraft-cli mcp` (бинарь в ~/bin, паттерн audio-analyzer).
2. **ZCode-плагин ВЫВЕДЕН из прод-пути кокпита.** Обоснование владельца: (а) массовость — пользователи не имеют ZCode, зависимость непереносима для дистрибуции; (б) экономия ресурсов. Плагин остаётся dev-tooling'ом агентских сессий (Папа/дети), в продукт не входит.
3. **«Жёстко кодить на Rust»**: вся логика кокпита — Rust-ядро (Tauri main): MCP-клиенты, staging/manifest, Acceptance Rate, DawBackend-фасады. React — только вид. Этап 2 = сплошной Rust-кодинг по списку Папы (adopt_loop C1, настоящий get_bus_state через session.inspect, staging manifest, accept_part/reject_part, run_self_check, events) + контракт-тест v0.5.0↔v0.20.1.
4. Спайк-факты (docs/engine-spike-report.md): холодный старт 0.15 с (vs 8 с), inspect/import <1 мс, bounce 1.04 с + LUFS, песочница в движке.
