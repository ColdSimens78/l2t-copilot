# Спека экранов кокпита v0 — поэкранная интеракция для UI-модуля

**Версия:** 0.1 · **Автор:** UI-спека · **Дата:** 2026-11-22
**Статус:** ТЗ для UI (после моков); коммит выполняется мейнтейнером
**База:** USER FLOW v1 (память, draft автора + правки архитектуры) · proposal v0.4 §3–§5 ·
`docs/ipc-contract.md` v0.1
**Как читать:** имена компонентов — из proposal §4.5; каждая интерактивная
кнопка имеет строку «→ контракт» (команда/событие из ipc-contract v0.1).
Зазоры контракта помечены ⚠ и собраны в §7 (предложения к v0.2, ждут
вердикта мейнтейнера) — они НЕ блокируют разработку: см. правило фич-флагов §7.
Без кода: только словари, состояния, переходы и маппинги.

---

## 0. Сквозные правила (действуют на каждом экране)

1. **Кнопка = MCP-инструмент.** Ни одной кнопки без строки «→ контракт».
   Если действие — последовательность вызовов, это указано явно (в логе
   видны все вызовы).
2. **UI = проекция шины.** Источники данных: `get_bus_state` (pull перед
   действием) + события `bus_log` / `suggestion_updated` / `host_status`.
   Локальный React-state — только эфемерщина (выделения, открытые панели,
   оптимистичные статусы). После перезапуска кокпита всё восстанавливается
   из manifest.json + `get_bus_state`.
3. **Формат нот = midi_io** (`{note, start, end, velocity, channel}`, тики;
   `ticks_per_beat` + `bpm` — из конверта `load_notes` для перевода в
   доли/секунды). Никаких локальных альтернативных структур.
4. **Каждая панель имеет 4 состояния:** normal / empty / loading / error —
   перечислены per screen; пустые состояния всегда говорят, что делать
   дальше (никогда не пустая пустота).
5. **AI-индикация трёхуровневая + AI Dock** (USER FLOW v1): <300 мс — без
   индикации; 0.3–10 с — канал «дышит» (пульс), призраки вплывают; >10 с —
   строка AI Dock с `source_tool` и `[отменить]`. **Никогда не модальные
   спиннеры.**
6. **Ошибки = toast с текстом JSON-RPC + каталог «починить за меня» (§6).**
   Таймаут превращает ядро в inspect-вердикт (proposal §6.2) — UI НЕ
   ретраит сам, показывает `⏱ → inspect → ✓/✗`.
7. **Ничего в DAW-сессию до accept** (proposal §3.3). Единственные
   мутаторы сессии — команды, помеченные ⚙-мутатор в матрице §5.
8. **Ручной режим — базовый.** Ни один экран v0 не требует LLM; мозг
   (qwen_bridge/автопилот) — этап 4.

## 2. Экраны

### S0 · «Разбудить движок» (оверлей; USER FLOW Screen 0)

**Назначение:** гарантировать, что DAW-движок поднят, до любых действий.
**Триггер показа:** при старте кокпита и при каждом `host_status {engine}`
со значением ≠ `up`.

**Состояния:**
- `hidden` (normal) — engine = `up`; оверлея нет.
- `waking` (loading) — «Поднимаю редактор DAW…»; пульсирующая точка;
  текст «движку нужно ~8 с на прогрев» (урок PoC); видима попытка №
  («повтор 2/5»); кнопка [Отмена ожидания] (закрывает оверлей, кокпит
  остаётся в режимах без DAW: анализ/генерация работают).
- `down` (error) — «Хост не отвечает»: причины + [Починить за меня] +
  [Настроить путь к DAW] (v0: текстовая подсказка в настройках).

**Переходы:** `host_status {engine:'up'}` → скрыть оверлей → S1.
**Маппинг:** старт → `get_bus_state` (pull); далее — событие
`host_status {engine}` → оверлей + точка в TopBar.
**Фикс:** [Починить за меня] → wake-последовательность ядра (поднять
редактор → подождать → retry; контракт шины, правило 5). Команды wake в
контракте нет — это внутренняя механика ядра, UI видит только
`host_status`. → контракт: **нет команды, только события** — так и
показывать.

### S1 · Пустой проект / Drop лупа (empty-состояние главной)

**Назначение:** получить луп в workspace и запустить анализ.
**Компонент:** центральная drop-зона (state S1 = центр до появления X-Ray).

**Состояния:**
- `empty` — «Перетащи WAV/FLAC сюда» + [Выбрать файл] (файловый диалог ОС).
- `analyzing` (loading) — «Слушаю луп…»; ≤10 с обычно (анализ 55–91 мс
  после загрузки — dock-строка почти мгновенная); пульс drop-зоны.
- `error` — три варианта: файл вне workspace (правило 1 шины) /
  неподдерживаемый формат / анализ упал. Каждый — toast + см. §6.

**Кнопки и маппинг:**
- Drop файла (абсолютный путь) или [Выбрать файл] → контракт:
  `analyze_loop {path}` → ответ `XRayReport` → переход S2.
- ⚠C5 (вне workspace): [Поместить в workspace и анализировать] →
  предложение к контракту §7 (C5: `copy_into_workspace`); до вердикта —
  toast с инструкцией «скопируй файл в workspace» и disabled-кнопкой.

**Переходы:** XRayReport → S2 (правая панель) + заполнение
`<SourceLoopCard/>` (S3) именем/длительностью файла.

### S2 · Loop X-Ray (правая AI Panel, вкладка 1; USER FLOW Screen 2)

**Назначение:** «событие доверия» — рассказать, что за луп, и применить
настройки к сессии (opt-in).
**Компонент:** `<XRayPanel/>` (§4.5).

**Состояния:**
- `normal` — отчёт: TEMPO / KEY / LOUDNESS / СПЕКТР / РИТМ (состав полей =
  `XRayReport`: bpm, bpm_confidence, bpm_alt?, key, key_confidence,
  key_relative?, lufs, true_peak, bands, onset_density).
- `low-confidence` (variant normal) — conf < ~70 % → строка приглушена +
  жёлтая; TEMPO при наличии `bpm_alt` показывает обе гипотезы
  (`[60.1] [120.2 — возможно ×2]` сегмент-выбор, USER FLOW: выбор за
  человеком); KEY показывает «≡ C major (отн.)» при `key_relative`.
- `error` — «Анализ не удался» + [Повторить] (→ `analyze_loop` заново) +
  §6.

**Кнопки и маппинг:**
- [✓ Применить к сессии: BPM + key-маркер] → контракт: ⚠C1 — команды
  `adopt_loop` в v0.1 НЕТ (есть только в dawbackend-spec). Спека пишется
  под `adopt_loop {bpm, key, source}` (§7, предложение C1); до вердикта
  кнопка disabled + тултип «ждёт согласования контракта (C1)». Выбранный
  BPM — из сегмента `bpm_alt`, не всегда верхний.
  Это opt-in: автоприменения нет никогда (правило 4 шины; #1702).
- Graceful degradation (по факту ядра l2t-core, 49df4a8): в текстовом
  режиме анализатора `bpm_alt` и `key_relative` приходят всегда `null` —
  сегмент-контрол и бейдж относительной тональности просто НЕ рендерятся,
  когда поля null; UI не должен этого считать ошибкой. Появятся поля —
  контролы появятся сами (данные управляют UI).
- [→ Сгенерировать партии] → чисто локальный переход: фокус на левую зону
  S3 (каналы предзаполнены key/bpm из отчёта). Команды нет — это навигация.

**События:** результат `analyze_loop` (ответ команды) → панель;
`bus_log ok` → dock. `get_bus_state` после adopt обновит TopBar
(BPM/key_marker) — когда C1 принят.

### S3 · Channel Rack (левая зона; USER FLOW Screen 3)

**Назначение:** 3 генератора = 3 канала (bass/chords/drums) + Source Loop
как четвёртый (🔒 референс). Генерация, параметры, версии, accept.
**Компонент:** `<StagingPanel/>` + `<PartChannel/>`×3 + `<SourceLoopCard/>`.

**Состояния канала (`<PartChannel/>`):**
- `idle` (empty) — большая кнопка «Сгенерировать бас/аккорды/бит» +
  подпись-подсказка (что канал сделает).
- `generating` (loading) — пульс (3-уровн. индикация); кнопки канала
  disabled; >10 с → строка в AI Dock с `[отменить]` (семантика §AI-Dock).
- `normal` — карточка: `<GhostPreview/>` (мини-превью нот, midi_io) +
  rationale-строка (одна строка из suggestion.rationale) + confidence +
  `source_tool` мелким шрифтом + `<ParamChips/>` + `<VersionHistory/>` +
  `<SuggestionActions/>` [▶] [↻] [✓] [✕].
- `error` — «Генерация не удалась» + [Повторить] + §6.
- `accepted` (после accept) — статус-бейдж «в сессии, дорожка N» (из
  ответа accept_part), превью остаётся для сравнения; [↻] создаёт НОВОЕ
  предложение (v(N+1)) — повторный accept, §5.2 proposal.

**Chips → params (словарь midi-gen v3):**
- bass: `style` = basic|octaves|syncopated|walking|sub; `bars`.
- chords: `voicing` = voiceled|block; `bars`.
- drums: `style` (basic), `variation` (fill на 4-м такте), `bars`.
- `key`/`bpm` НЕ чипы: подставляются из сессии (если adopt был) или из
  выбранного в X-Ray (если нет); отображаются в канале read-only серым —
  сессия = источник истины (правило 4 шины).

**Кнопки и маппинг (per канал):**
- [Сгенерировать] / клик chip → контракт: `generate_part {tool, params}`
  (tool: bass|chords|drums) — первый вызов канала;
  `regenerate {part, params_diff}` — последующие (diff только изменённых
  chip'ов; в чип-стате виден diff `style: basic → syncopated`).
- [▶ превью] → контракт: ⚠C2 — превью-WAV в контракте не определён;
  конвенция-предложение §7 (C2: `staging/<part>_v<N>.wav` рядом с .mid,
  рендерит сайдкар GM-синт). UI ищет файл по конвенции; нет файла →
  кнопка disabled + тултип «рендер превью…» (ядро рендерит асинхронно
  после suggestion_updated; готовность = появление файла; v0 без
  события — поллинг при открытии карточки, дешевле не делать). Проигрывание
  — HTML audio, слои mute/solo через `<ScenesBar/>`.
- [✓ Принять] → контракт: `accept_part {part, version}` (⚙-мутатор) →
  ответ `imported_tracks[]` → бейдж «дорожка N» + перезапрос
  `get_bus_state` (обновить S5). **Accept = передача источника истины**
  (USER FLOW): призрак материализуется, правка нот теперь только в
  SoundCraft.
- [✕ Отклонить] → контракт: `reject_part {part, version}` → версия
  помечается rejected (остаётся в истории).
- [⤓ Принять всё готовое] (опционально, сверху панели) → контракт:
  цикл `accept_part` по всем каналам в `auditioned` с последней версией;
  в логе — отдельные вызовы, частичный отказ = toast по конкретному
  каналу.

**События:** `suggestion_updated {part, version, suggestion}` →
перерисовать конкретный канал (+ GhostLayer в S4); `bus_log` → dock;
`host_status` → если down в момент accept — error-состояние канала + §6.

**VersionHistory:** клик по прошлой версии = показать её (локальное
выделение + перерисовать GhostPreview/GhostLayer); [✓] принимает именно
выбранную версию (version в accept_part). «Принять v1 после v3» —
поддержано.

### S4 · Ghost Notes (центр, тумблер [Призраки]; USER FLOW Screen 4–5)

**Назначение:** видеть предложения нотами, наложенными на референс, до
accept; compare слоёв.
**Компонент:** `<PianoRollView/>` (v0 минимальный: zoom, без
velocity-lane — решение мейнтейнера).

**Состояния:**
- `empty` — «Нет предложений — сгенерируй в Rack» + стрелка-подсказка к
  левой зоне.
- `normal` — наложение: луп-референс (серым, из SourceLoopCard) + бледные
  слои принятых каналов; палитра за каналом (bass/chords/drums), единая с
  мини-превью; hover канала в Rack подсвечивает его слой (локальная
  связь компонентов); подписи rationale — на карточках, не здесь.
- `error` — нет (данные локальные из manifest + событий); при
  рассинхроне с manifest — toast + перезапрос `get_bus_state`.

**Взаимодействия:** zoom (колесо/pinch); клик по ноте — ничего (read-only,
§3.1); переключение тумблера — локально. Данные — те же
`suggestion_updated`; тики → доли через `ticks_per_beat` конверта.

### S5 · Playlist read-only (центр, тумблер [Playlist])

**Назначение:** контекст — куда прилетят партии; что уже есть в сессии.
**Компонент:** read-only проекция `BusState.tracks[]`.

**Состояния:**
- `empty` — «Сессия пуста — импортируй принятые» (если tracks[] пуст).
- `normal` — дорожки из `get_bus_state`; принятые партии подсвечены
  палитрой канала; маркеры (key/структурные) — флажки на таймлайне.
- `error` — «Нет данных: движок спит» + [Разбудить] → S0-оверлей.

**Маппинг:** открытие тумблера → `get_bus_state` (pull); после каждого
accept_part — перезапрос; `host_status` ≠ up → error-состояние. Никаких
правок/drag&drop (v0 — read-only, §3.1; правки аранжировки — v1).

### S6 · Self-Check (правая AI Panel, вкладка 3; USER FLOW Screen 6)

**Этапность:** панель — этап 2 (proposal §10.3), но вкладка с empty-state
закладывается в этапе 1 (каркас не переделывать).

**Назначение:** светофор «луп → микс» после bounce; перепроверка
тональности ПОСЛЕ завершения аранжировки (правило 7 шины).

**Состояния:**
- `empty` — «Сделай bounce в SoundCraft (File → Export) и перетащи WAV
  сюда». В v0 bounce делает человек (как B.0); путь → шаг ниже.
- `loading` — «Слушаю микс…» (run_self_check: анализ + compare).
- `normal` — строки светофора по `SelfCheckReport`:
  - Тональность: `key_match:true` → ✓; `false` → ✗; относительная (через
    keys_match-семантику ядра) → ⚠ «≡ параллельная — ок» (правило 7).
  - Темп: `tempo_match` ✓/✗ (+ толкование ×2, если ядро вернёт).
  - Громкость: `lufs_delta` → ✓ в цели / ⚠ «до Spotify −14: +7.3 dB».
  - Полосы: `bands_delta` — «что добавили слои» против плана X-Ray.
- `warn` — жёлтые строки с фикс-кнопками (см. §6).
- `fail` — ✗-строки + [Починить за меня].

Критерии строк считаются на UI из полей отчёта (контракт v0.1 отдаёт
`verdict` только ok/fail — вопрос (c) ядра висит за мейнтейнером; строковый
светофор UI делает сам, не ломая схему): `key_match:false` → ✗-строка;
`tempo_match:false` → ✗-строка; `|lufs_delta| > 2 dB` → ⚠-строка «до
цели +X dB»; иначе ✓. Бейдж общего итога — контрактный `verdict`
(ok → зелёный, fail → красный). Если мейнтейнер определит verdict-level warn
— бейдж расширится, строки не изменятся.
- `error` — bounce-файл не читается / вне workspace (§6).

**Кнопки и маппинг:**
- Drop bounce-WAV / [Выбрать файл] → контракт: `run_self_check
  {bounce_path}` → ответ `SelfCheckReport` → светофор.
- [normalize до цели] → контракт: ⚠C3 — рендера/нормализации в v0.1 нет
  (предложение §7:暴露 daw.render для хостов с bounce_mix). До вердикта —
  инструкция «поставь галку normalize при экспорте в SoundCraft».
- [Отчёт .html] — этап 2 (§10.3), кнопка disabled в этапе 1.

### S7 · Bus Inspector (drawer, свёрнут; proposal §4.4)

**Назначение:** прозрачность — живой лог шины.
**Состояния:** `collapsed` (кнопка ▤ в TopBar) / `open`.
**Состав v0:** только лог. Чат-инпут показывается disabled с подсказкой
«чат вернётся с автопилотом (этап 4)» — USER FLOW отложил чат целиком.
**Маппинг:** событие `bus_log {ts, tool, command, status, ms}` → строка
лога; фильтры (по tool, по status) — локальные. Внутренние шаги ядра
(inspect после таймаута, wake-цикл) появляются в логе как обычные вызовы
— UI ничего не додумывает.

## 3. AI Dock (постоянная нижняя строка; USER FLOW v1)

**Назначение:** видимость долгих операций + прозрачность `source_tool`;
>10 с — единственное место «подожди». Dock НЕ претендует на фокус окна
(Tauri #11814 — approved-кверк OSS-разведки: no-focus на Linux невозможен,
проектируем без этого требования).
**Состав строки:** `● ИИ: [tool] — [действие]… [отменить]` (pending) /
итоговые статусы. Отображается последняя активная операция + счётчик
фоновых; история — в drawer (S7).

**Форматы строк по `bus_log` (шаблоны):**

| Источник | Статус | Шаблон строки |
|---|---|---|
| локальный запуск (UI знает о команде с момента вызова) | pending | `● audio-analyzer: analyze_loop — слушаю луп…` |
| « | pending | `● midi-gen: generate_part (bass) — генерирую бас…` |
| `bus_log` | `ok` | `✓ midi-gen: generate_part (bass) — готово · 0.3 с → слой bass v1` |
| `bus_log` | `ok` | `✓ soundcraft: accept_part (bass v2) — дорожка 7 создана` |
| `bus_log` | `timeout` | `⏱ soundcraft: import_midi — таймаут 30 с → проверяю состояние…` |
| (inspect ядра — приходит следующим bus_log) | `ok` | `✓ inspect: трек 7, 4 ноты — операция прошла, ответ потерян` |
| `bus_log` | `error` | `✗ core: run_self_check — файл не читается · [починить за меня]` |

**Человеческие фразы действий (словарь):** analyze_loop → «слушаю луп»;
generate_part → «генерирую бас/аккорды/бит»; regenerate → «перегенерирую
(изменено: style)»; accept_part → «передаю в сессию»; reject_part →
«отклоняю версию»; run_self_check → «проверяю микс»; adopt_loop (C1) →
«применяю настройки лупа».

**[отменить]:** v0 = локально скрыть строку + игнорировать последующий
`suggestion_updated` этой операции (без серверной отмены; stdio-запрос не
отменяется); подпись честная — «отменить показ». Серверный cancel — ⚠C4
(§7, v1).

**Правило pending:** bus_log не имеет статуса «start» — dock-строка
pending рисуется локально с момента вызова команды самим UI (в v0 все
команды инициирует UI). Команды внешнего агента (ZCode) в v0 dock не
попадают (только в drawer-лог) — v1.

## 4. TopBar

- Точка engine: `host_status {engine}` → зелёная up / жёлтая пульс
  waking (клик → S0-оверлей) / красная down.
- BPM и key: `get_bus_state {tempo, key_marker}` — обновление после
  adopt/accept (перепрос pull).
- Сессия (имя/path): ⚠C6 — `BusState` не содержит session_name; v0 —
  показываем только BPM/key; имя в заголовке окна (предложение §7).
- Транспорт: ⚠T1 — команд play/stop в контракте v0.1 нет; v0 транспорт —
  read-only отображение и нажатие открывает подсказку «управляй
  транспортом в SoundCraft» (§3.2 proposal: хост — движок). Кнопки
  play/stop — кандидат в контракт v0.2/v1 (§7).

## 6. Каталог ошибок и «починить за меня» (USER FLOW v1)

| Ситуация | Где видна | UX | Фикс-действие |
|---|---|---|---|
| engine down/waking (host_status) | S0-оверлей, TopBar, S5 | оверлей с прогрессом попыток | [Починить за меня] = wake-цикл ядра (правило 5 шины); UI — только отрисовка |
| файл вне workspace (правило 1) | S1, S6 (bounce) | toast «файл вне workspace» | ⚠C5: [Поместить в workspace и анализировать]; до вердикта — инструкция копирования |
| неподдерживаемый формат | S1 | toast с форматом | [Выбрать другой файл] |
| таймаут MCP (правило 2) | dock, drawer | `⏱ → проверяю состояние…` — ядро делает inspect сам | ничего нажимать не надо; вердикт приходит следующим bus_log |
| ошибка/паника сервера (правило 3) | toast | текст JSON-RPC error полностью | [Повторить] на месте ошибки |
| accept при спящем хосте | S3 канал | error-статус канала | [Починить за меня] → S0-wake → повтор accept по кнопке канала |
| soundfont не найден (сайдкар, C2) | S3 [▶] | кнопка disabled + тултип | v0: подсказка «превью появится после настройки рендера»; WYSIWYG — этап 3 |
| Self-Check fail: тональность | S6 | ✗ + толкование (Em ≠ Am — реальный кейс PoC) | [Починить за меня] = показать, какой слой конфликтует (v1); v0: список каналов к перегенерации |
| Self-Check warn: громкость | S6 | ⚠ + дельта до цели | [normalize до цели] (⚠C3) или инструкция экспорта |
| proxy мозга недоступен | S7 (этап 4) | toast «Мозг недоступен — ручной режим работает» | продолжение в Manual — не блокер (правило 8 §0) |

Общее правило: каждый error-state несёт (а) причину текстом, (б) одну
главную кнопку-фикс, (в) ссылку-разворот «подробнее» (drawer-лог,
отфильтрованный по tool).
