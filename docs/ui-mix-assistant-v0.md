## 0. Сквозные принципы панели

1. **«ИИ не рисует фейдеров».** Панель не содержит ни одного фейдера,
   ручки, слайдера, knob'а. Она — **список карточек-предложений** с
   кнопками [Применить]/[Отклонить]/[Откатить]. Ручки живут в микшере
   SoundCraft (граница §3.2 proposal «ни одного фейдера в кокпите» — эта
   спека её НЕ двигает; что двигается, так это причина: раньше агент не
   лез в микс, потому что «нет инструментов», теперь инструменты
   (`mix_*` v0.2.2) есть — значит граница переносится с «нет инструментов»
   на **«нет автономии»**: применяет только человек).
2. **Ассистент = вторые уши, не вторые руки.** Каждое предложение несёт
   **формулу из метрик** (LUFS-дельта, Δ полос, фаза, баланс snapshot'а) —
   не «поверь мне». Человек всегда может открыть SoundCraft и сделать
   то же самое руками; ассистент экономит время поиска «что крутить».
3. **Кнопка = команда; UI = проекция шины.** Применение предложения —
   вызов ядра; ядро — движковый `mix_*`. В инспекторе (S7) видны все
   фактические вызовы движка, как и везде.
4. **Undo — через обратную команду, НЕ через движковый undo-стек.**
   Критичный дизайн-аргумент (факт разведки №8): `edit.undo` движка
   откатывает последнее действие **движка вообще** — между применением
   предложения и кнопкой [Откатить] человек мог крутить что-то в
   SoundCraft, и общий undo откатил бы **чужое**. Поэтому revert =
   явная обратная команда из сохранённого `current` (mix_volume обратно
   на прежнее значение). Откат «своим» действием — предсказуем и безопасен.
5. **Одно предложение = одно действие.** Карточка меняет ровно один
   параметр одного трека (гейн ИЛИ пан ИЛИ mute). Никаких пакетов
   «гейн+пан+EQ одной кнопкой» в v0 — это ломает и понятность, и откат.
   Пакетные предложения — v1 (после накопления статистики, работают ли
   связки).
6. **Данные управляют UI** (паттерн bpm_alt): полей, которых нет в
   snapshot'е или отчёте анализа, панель не рисует.
7. **Без DAW панели нет.** Позиционирование v2.2 (десктоп-компаньон,
   самодостаточен без DAW) соблюдается честно: микс живёт в движке —
   без подключённого движка вкладка говорит об этом прямо (§3 empty/error),
   остальные панели продолжают работать.

## 1. Место панели

| Кандидат | Вердикт | Почему |
|---|---|---|

     включается флагом C8

**Типы карточек v0** (все — ровно одно действие, принцип §0.5):

| Тип | Действие (движковая команда) | Откуда метрика |
|---|---|---|
| **GAIN-BALANCE** | `mix_volume {tracks:[id], delta_db}` | mix_snapshot (разброс громкостей) + analyzer-полосы bounce vs луп |
| **PAN-SPLIT** | `mix_pan {tracks:[id], pan}` | Δ mid-полосы + центр-скученность snapshot'а |
| **MASTER-TARGET** | не применение, а **ссылка** на готовый P-Master экспорт с target | LUFS bounce vs цель (Spotify −14 / Apple −16) |
| **PHASE-CHECK** *(диагностика, без применения)* | нет — карточка-предупреждение «проверь фазу трека X» | phase correlation анализатора < порога |

Примечание: `mix_volume`/`mix_pan`/`mix_mute` v0.2.2 **уже в контракте** —
но UI НЕ дёргает их для применения предложений (применение только через
`apply_mix`, C8 — чтобы журнал и откат были привязаны к id предложения).
Прямой вызов остаётся ровно один: A/B-мутька (§4).

**Словарь карточки (данные, не UI):**

```
mix_suggestion = {
  id,                    // резолвится ядром в mix_*-вызов при apply
  target:  {track_id, track_name},
  kind:    'gain_balance' | 'pan_split' | 'master_target' | 'phase_check',
  current: {volume_db | pan},          // из mix_snapshot на момент анализа
  proposed:{delta_db | pan},           // одно действие (§0.5)
  delta_display: "+1.5 дБ" | "L 0.3 → L 0.55",
  rationale: "<одна строка из метрик>",
  metrics: {lufs_delta?, band_delta?, phase?},   // числа-доказательства
  confidence: 0.0..1.0,
  source: "l2t-core: mix_snapshot + analyzer compare"
}
```

Паттерн тот же, что ghost-notes `suggestion` (proposal §5.1): данные с
`rationale`+`confidence`+`source` — ИИ объясняется одной строкой, человек
решает. Домен другой — контракт другой (§5).

## 3. Состояния панели

| Состояние | Условие | Что рендерится |
|---|---|---|
| `empty` (нет bounce) | предложений ещё не запрашивали | «Сделай bounce и пришли сюда: перетащи WAV или [Взять bounce из Self-Check]» (локальная связка вкладок, если S6 уже анализировал) |
| `no-engine` (вариант empty) | `engine ≠ up` (из mix_snapshot) | «Микс живёт в DAW-движке. Подключи SoundCraft (клик по точке движка)» — остальные вкладки работают (принцип §0.7) |
| `analyzing` (loading) | `mix_suggest` в полёте | «Слушаю микс…» + шаги: «bounce → анализ → сверка с snapshot» (ядро отдаёт фразы этапов через bus_log-паттерн); >10 с → AI Dock-строка; никогда не модальный спиннер |
| `normal` | есть предложения | СВОДКА + ПРЕДЛОЖЕНИЯ + ПРИМЕНЕНО (§2) |
| `no-suggestions` (вариант normal) | анализ прошёл, предложений 0 | «Заметных перекосов не нашёл — микс в балансе с лупом. Можно переанализировать после изменений» — честный положительный ответ |
| `error` | см. каталог ниже | причина + фикс-кнопка, остальная панель/вкладки не блокируются |

**Refresh-триггеры:** открытие вкладки → `mix_snapshot` (pull, дёшево);
кнопка [▲ переанализ] → `mix_suggest` заново (после изменений микса
человеком); после apply/revert → повторный `mix_snapshot` (сводка живая).
Событий в контракт не добавляем (паттерн acceptance-панели: pull + осознанная
staleness).

**Каталог ошибок** (дополняет §6 ui-screens): bounce вне workspace →
[Поместить в workspace] (C5-путь); движок уснул между анализом и применением
→ [Разбудить] (S0-wake) → предложение остаётся в списке, статус «проверить
snapshot перед применением»; analyzer упал → [Повторить]; snapshot
пуст (нет треков) → «Микс пуст — импортируй партии (S3)».

## 4. Взаимодействие с карточкой

- **[✓ Применить]** → `apply_mix {suggestion_id}` (C8) → ядро резолвит id
  в один `mix_*`-вызов → карточка перемещается в «ПРИМЕНЕНО» +
  перезапрос `mix_snapshot` (сводка обновилась — пользователь видит
  новое текущее). Оптимистично: статус «применяю…» сразу, при ошибке —
  откат статуса + toast с текстом (паттерн accept_part).
- **[✕ Отклонить]** → карточка сворачивается в однострочный хвост
  («отклонено: Bass +1.5 dB · [вернуть]»); решение — локальное, в
  manifest НЕ пишется (см. §8, вопрос Папе).
- **[▶ A/B]** → прямой `mix_mute {tracks:[target], on:true}` (контракт
  v0.2.2, кнопка = команда) + бейдж на карточке «A/B: трек заглушен —
  сравни» и глобальный бейдж в сводке «1 трек в A/B»; повторный клик —
  `mix_mute {on:false}`. A/B не считается «применением» — не попадает в
  ПРИМЕНЕНО и не требует отката (mute виден в snapshot и в SoundCraft).
- **[Откатить]** (в ПРИМЕНЕНО) → `revert_mix {suggestion_id}` (C8) →
  ядро применяет сохранённый `current` обратной командой (принцип §0.4);
  карточка возвращается в ПРЕДЛОЖЕНИЯ со статусом «применение откатено».
- **MASTER-TARGET** — не применяется из панели: кнопка-ссылка
  [Экспорт с target −14] ведёт в готовый P-Master экспорт-путь
  (target 'loop'/Spotify/Apple уже в контракте v0.2.2 после ревью №4).
  Панель не дублирует мастеринг — она на него показывает.

## 5. Маппинг на контракт v0.2.2 → предложение C8 (контракт v0.3)

**Уже есть (панель пользуется без изменений контракта):**

| Что | Команда (v0.2.2) | Где в панели |
|---|---|---|
| Текущие значения (current/сводка) | `mix_snapshot` → `{engine, tracks[] {volume_db, pan, mute, solo}}` | СВОДКА, current карточек, no-engine-состояние |
| A/B-мутька | `mix_mute {tracks, on}` | [▶ A/B] |
| Мастер-цель | P-Master экспорт с target (v0.2.x) | MASTER-TARGET-ссылка |
| Отчёт bounce (LUFS/TP) | bounce-ответ движка (через ядро) | сводка Master-строки |

**Зазор C8 — три команды (предложение к v0.3):**

| Команда | Вход | Выход |
|---|---|---|
| `mix_suggest` | `{bounce_path, loop_report?}` (loop_report — опциональный reuse XRayReport/compare из S2/S6; без него — сравнение с целями) | `MixSuggestions {summary {bounce_lufs, loop_lufs?, targets}, suggestions[]: mix_suggestion}` |
| `apply_mix` | `{suggestion_id}` | `{applied: {command, params, result}}` — ядро резолвит id в ровно один `mix_*` (§0.5), пишет в журнал |
| `revert_mix` | `{suggestion_id}` | `{reverted: {command, params}}` — обратная команда из сохранённого `current` |

**Семантика для ядра (l2t-core):** `mix_suggest` = композит
штатных шагов (анализатор на bounce + `mix_snapshot` + сравнение — вся
цепочка уже работает в run_self_check и X-Ray; новое — только порождение
списка mix_suggestion и хранение id→(current, action) для revert).
Плагинные предложения (EQ-маскировка через `mix.insert_param`) — **не v0**:
самоописание ручек через `session.inspect` (разведка №8 §2) даёт путь, но
плагинное применение требует свойства «безопасно откатить» (insert_remove)
— отдельное предложение v1.

**Фич-флаг (паттерн ui-screens §7):** вкладка [Микс] рендерится и без
C8 — в режиме read-only СВОДКИ (snapshot уже в контракте, польза сразу:
«что у меня в миксе» глазами, без фейдеров). Раздел ПРЕДЛОЖЕНИЯ + кнопки
— disabled с тултипом «C8 — ждёт согласования контракта». После вердикта
— один флаг включает.

**Что НЕ добавляем:** события `mix_suggestions_updated` (pull-паттерн
acceptance-панели; предложения волатильны — §6), пакетный apply
(нарушает §0.5), автоматический re-suggest после каждого apply
(перезапрос руками — [▲ переанализ]; автоматика = кольцо итераций,
которое P-Master ограничивает 2–3 вручную).

## 6. Undo-культура (детально, §0.4 развёрнуто)

1. **Revert = обратная команда**, не `edit.undo`. Ядро хранит
   id → (current, applied-команда) и на `revert_mix` применяет `current`
   штатным `mix_*`. Аргумент против undo-стека: он общий с человеком —
   между [✓] и [Откатить] человек мог крутить SoundCraft, undo унёс бы
   чужое действие. (Движок «откатывает» — но своим действием, что и
   требовалось.)
2. **Окно отката — сессия кокпита.** ПРИМЕНЕНО волатильно: до перезапуска
   кокпита откат кнопкой; после — панель честно пишет «применения этой
   сессии откатываются кнопкой до перезапуска; после — руками в
   SoundCraft» (значения ПРИМЕНЕНО можно подсмотреть в сводке/SoundCraft).
   Персист списков apply/revert — v1 (если Ilmir скажет, что нужно).
3. **Всегда видно, что применено:** раздел ПРИМЕНЕНО с треками, дельтами,
   временем; mute-состояние A/B — бейдж в сводке. Человек ни в какой
   момент не обязан помнить, что ИИ менял.
4. **Откат не каскадный:** каждое применение откатывается независимо
   (одна карточка — одно действие — один revert).

## 7. UX-тексты (готовые к вставке)

- Empty: «Пришли bounce — ИИ измерит баланс и предложит 2–3 конкретных
  движения ручек. Ручки останутся в SoundCraft: применяем только по
  кнопке.»
- No-engine: «Микс живёт в DAW-движке — подключи SoundCraft (точка
  движка в шапке). Остальное работает и без него.»
- No-suggestions: «Заметных перекосов не нашёл — баланс близок к лупу.»
- Приватность/локальность (внизу): «🔒 Анализ локальный: bounce, snapshot
  и метрики не покидают машину.»
- Шапка раздела предложений: «ИИ измерил — ты решаешь» + мелким:
  «каждое применение — одно действие, откатывается кнопкой».
- Санкционирующая подпись сводки: «Только цифры из snapshot — ручки
  крути в SoundCraft».
