# Этот репозиторий: 100% кода написано AI-агентами

**Не маркетинг — инженерная дисциплина.** Каждый файл в этом репозитории
(`crates/`, `ui/`, `src/`, `tests/`, `docs/`) написан агентскими сессиями.
Человек — основатель проекта — задаёт видение, принимает решения и
ратифицирует архитектуру; агенты исследуют, специфицируют, кодят, тестируют
и документируют. Ревью каждого коммита — обязательный гейт.

> Продукт при этом — не эксперимент: это рабочий инструмент
> Loop-to-Track для музыкантов (см. [README](README.md)).
> Методология разработки — часть продукта: мы строим AI-native
> приложение AI-native способом.

## Команда: роли вместо имён

| Роль | Зона ответственности |
|---|---|
| **Lead** | Архитектура, ревью всех коммитов, релизы, координация, финальные решения |
| **Desktop Engineer** | Rust-ядро: MCP-клиенты, engine slot, staging/manifest, превью |
| **Frontend Engineer** | Кокпит: React/Tauri, экраны, призрачные ноты, дизайн-система |
| **OSS Scout** | Постоянная разведка: библиотеки, лицензии, конкуренты, апстрим-патруль |
| **UX Architect** | Спецификации: поэкранные интеракции, метрики, контракты UX |
| **Founder** | Видение продукта, ратификация решений, приёмка |

Каждая роль — отдельная AI-сессия. Координация — через память проекта и
документы в репо, не через переписку. Подробная методология:
[docs/ai-development-methodology.md](docs/ai-development-methodology.md).

## Навыки, которые здесь демонстрируются

- **Product thinking & communication** — PRD с позиционированием (против
  Suno/Udio/Scaler), hero-сценарий, формулировка метрики успеха
  (Acceptance Rate) до написания кода, честная коммуникация ограничений.
- **AI assistant development** — проектирование и реализация MCP-серверов
  (stdio, bounded-ошибки, dual-SDK шимы), мультиагентная оркестрация с
  протоколом памяти, rate-limit и квота-протоколы.
- **Full-stack development & debugging** — Rust-ядро (rmcp + tokio),
  Tauri v2 IPC, React-кокпит, Python MCP-серверы; отладка до живых
  интеграций с движком и анализатором.
- **Quality & metrics** — контрактные тесты (детерминизм байт-в-байт),
  golden-тесты версий движка, лицензионные гейты (0 копилефт в 118
  крейтах), instrumentация Acceptance Rate, CI на каждый push.

## Как это работает (конвейер)

```
Founder (видение, приёмка)
   ▼
Lead: декомпозиция → спецификации → раздача задач → ревью → релизы
   ▼                        ▼                        ▼
Desktop Engineer      Frontend Engineer       OSS Scout / UX Architect
(Rust-ядро, движок)   (кокпит, экраны)        (разведка, спеки)
   └──────── scoped commits ──► CI (pytest+cargo) ──► ревью Lead ──► push
```

Ключевые практики:

1. **Спецификация впереди кода.** Поэкранные спеки (состояния, переходы,
   маппинг «кнопка → команда») пишутся до React-кода — Фронтендер строит
   экраны, не задавая вопросов.
2. **Контракты, а не договорённости.** `docs/ipc-contract.md` — единый
   источник типов; версии с bump'ами; обе стороны (Rust/TS) обновляются
   синхронно.
3. **Ошибки превращаются в правила.** 7 правил «Контракта шины» в README —
   это документированные инциденты (таймаут ≠ отказ, песочница workspace,
   exponential duplicate, relative-key). Инцидент → правило → тест.
4. **Разведка до установки.** Каждый внешний инструмент (10 отчётов)
   проходит верификацию: лицензия по файлу, активность, red flags.
   Пример: из 7 предложенных MCP-серверов 0 прошли — 2 имени не существуют.
5. **Голос-политика.** Все тексты репо — нейтральный профессиональный язык
   от имени команды; внутренние процессы (сессии агентов, память, лимиты)
   не попадают в публичный репозиторий.
