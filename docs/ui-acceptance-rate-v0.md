**Статус:** ТЗ Фронтендеру (этап 2 по плану; спека впереди кода); не

## 0. Сквозные принципы панели

1. **Локальность — суть фичи, не деталь.** Вся статистика считается из
   `manifest.json` в папке проекта пользователя. Ноль облака, ноль
   телеметрии, ноль сетевых вызовов. Это отражено в самом интерфейсе (§6).
2. **Честность малых выборок.** Панель никогда не делает громких выводов
   из 2–3 решений: до ~10 решений показывается каveat «осмысленно от
   ~10 решений», прокси-метрики показываются как факты, а не как оценки
   («хорошо/плохо»).
3. **Нет loading-состояния.** Данные локальные, чтение manifest + ответ
   C7 — один кадр. Спиннер на этой панели = ошибка дизайна.
4. **Данные управляют UI.** Режимы (agent/autopilot), audition_count и
   прочие поля, которых в данных пока нет, не рендерятся (graceful hide,
   как bpm_alt в ui-screens S2). Появятся данные — появится элемент.
5. **Метрика = жест человека.** Панель только отображает; на вычисление и
   запись решений она не влияет (решения — accept/reject в S3, §5.3
   proposal).

## 1. Где живёт панель

| Кандидат | Вердикт | Почему |
|---|---|---|
| **Вкладка AI Panel** (4-я: [X-Ray][Генерация][Self-Check][Статистика]) | ✅ **рекомендовано** | AI Panel — семейство «вероятностей доверия»: X-Ray = доверие лупу, Self-Check = доверие миксу, Статистика = доверие агенту во времени. Один источник данных (ядро/manifest), одна механика вкладок, empty-состояние ничего не стоит |
| Раздел настроек | ❌ | Настройки открывают раз в жизни; метрика умирает. К тому же это данные, а не конфиг |
| Футер Channel Rack | ❌ | Захламляет рабочую зону; per-channel взгляд закрывается мини-бейджем на карточках (ниже) |
| Отдельное окно (FL-паттерн v1) | ⏸ v1 | Окна — этап v1 (TEAM BRIEFING v2); не для v0 |

**Решение:** вкладка **[Статистика]** в AI Panel (правая зона) +
**мини-бейдж** на каждой `<PartChannel/>`-карточке: `3/5` рядом со
статусом (только число accepted/total — ноль стоимости, живёт с этапа 1,
сам бейдж включается флагом этапа 2).

## 2. Что видит пользователь

```
┌─ [X-Ray][Генерация][Self-Check][Статистика*] ────────────┐ AI Panel
│                                                          │
│  «Ты оставляешь 6 из 10 предложений ИИ»      ▓▓▓▓▓▓░░░░  │ ← общая фраза
│                                               60%        │   + полоса
│ ──────────────────────────────────────────────────────── │
│  🎸 bass    3/5 (60%)   ●✓ ●✕ ●✓ ●✓ ●✕                   │ ← per-канал:
│  🎹 chords  2/3 (67%)   ●✓ ●✕ ●✓                         │   rate + числа
│  🥁 drums   1/2 (50%)   ●✓ ●✕                            │   + лента версий
│ ──────────────────────────────────────────────────────── │
│  режимы:  ручной 10                                      │ ← по режимам
│  ──────────────────────────────────────────────────────── │
│  факты генерации (прокси PRD §4):                        │
│  · chords: движение голосов ≤ 4 п/т (voiceled)           │
│  · bass:   5 ритмических позиций (syncopated)            │
│  · drums:  fill на 4-м такте (variation)                 │
│ ──────────────────────────────────────────────────────── │
│  🔒 всё локально — manifest.json в папке проекта,        │ ← приватность
│     без облака и телеметрии           [Скопировать сводку]│
└──────────────────────────────────────────────────────────┘
   * вкладка disabled + тултип «C7» до вердикта Папы (§5)
```

**Элементы:**
- **Общая фраза** — человекочитаемая формулировка метрики PRD §4
  («доля сгенерированных партий, которые пользователь оставил»). Полоса —
  доля от общего числа решений, не от партий.
- **Per-канал строки** — `accepted/total (rate%)` по каждому каналу;
  данные из ленты версий того же канала.
- **Лента версий** (version strip) — точка на каждую версию партии:
  зелёная = accepted, красная = rejected, серая = pending
  (generated/auditioned, ещё не решена); последняя версия выделена.
  Tooltip точки: дата + params-дифф («style: basic → syncopated»).
  Показывает главный сценарий пользы: регенерация улучшает принятие
  («после v2 начал оставлять»).
- **Режимы** — счётчики решений по mode (manual/agent/autopilot).
  v0: существует только «ручной» (честность атрибуции — §4); строки
  agent/autopilot появляются, когда появятся данные.
- **Факты генерации (прокси)** — авто-метрики PRD §4 (voice motion,
  pattern variety, drum variation) по последней версии каждой партии,
  как факты без оценок. Место вычисления — ядро (§4).
- **Строка приватности** + [Скопировать сводку] — текстовая сводка
  (значения, без params) в буфер обмена — для issues/отчётов PRD; тоже
  локальное действие.
- **Мини-бейдж на `<PartChannel/>`** — `3/5` у статуса канала; клик —
  открыть вкладку Статистика. v0: без графики, только число.

## 3. Состояния и переходы

| Состояние | Условие | Что рендерится |
|---|---|---|
| `no-data` (empty) | manifest пуст/нет ни одного решения | «Пока нет решений. Сгенерируй партии в Channel Rack — после первого ✓/✕ здесь появится статистика»; 3 мини-карты каналов серым с подписями, что будет измеряться |
| `first-data` | 1–9 решений | полный лэйаут + каveat малой выборки: «Метрика осмысленна от ~10 решений — пока это просто история» |
| `statistics` (normal) | ≥10 решений | полный лэйаут, каveat скрыт |
| `error` | manifest не читается / повреждён | «Статистика недоступна: manifest.json повреждён» + путь к файлу + подсказка «проверь файл или удали staging/ — статистика начнётся заново»; остальной UI не блокируется; мини-бейджи на каналах прячутся |
| loading | — | **не существует** (принцип §0.3) |

**Переходы (refresh-триггеры):**
- открытие вкладки → pull `get_acceptance_stats` (C7);
- локальный accept/reject (UI сам знает о решении — он его инициировал)
  → немедленный повторный pull; панель обновляется в тот же кадр, что
  бейдж канала;
- **событий для панели не требуется** (в контракт не добавляем event):
  решения внешнего агента (ZCode ходит к серверам напрямую, мимо ядра)
  подхватятся при следующем открытии вкладки — осознанная, честно
  задокументированная staleness; гонок нет, данные — один файл.

## 4. Данные и вычисления

- **Источник:** `manifest.json` (workspace/staging/). Схема записи —
  proposal §5.3: `{ts, part, version, params, source_tool, decision,
  mode, audition_count}`. **Реальность ядра сегодня** (Кодер, 49df4a8):
  запись минимальна `{part, version, decision, ts}`. Для панели нужны
  `params` (дифф-тултипы, связка прокси↔версия), `source_tool`,
  `mode`. Обогащение manifest до схемы §5.3 — семантический пункт ядра,
  **бандлится в предложение C7** (§5) — схема manifest в ipc-contract
  формально не зафиксирована, но C7 без неё пуст.
- **Прокси считает ядро, не генераторы** — уточнение к формулировке
  §5.3 proposal («прокси считают генераторы»): midi-gen MCP возвращает
  только файлы (схему генератора менять нельзя — это bump midi-gen),
  а ядро уже держит ноты каждой версии (midi_io) — max voice motion
  (аккорды: соседние аккорды, движение голосов), pattern variety
  (бас: число различных ритмических позиций), drum variation (ударные:
  наличие fill/вариаций) вычисляются при записи manifest-строки. Один
  пункт вычисления, ноль изменений схемы генератора, значения едут в
  manifest-строку и дальше через C7. Папе на вердикт вместе с C7.
- **mode — честная атрибуция:** v0 каждое решение инициирует UI →
  `mode: manual` всегда. Внешний агент (ZCode) вызывает серверы в своих
  stdio-сессиях — ядро этих вызовов не видит и атрибутировать не может
  (не притворяемся). `agent` появится, когда команды агента пойдут через
  ядро; `autopilot` — этап 4 (qwen_bridge). До тех пор строки режимов
  скрываются (принцип §0.4).
- **audition_count — зарезервировано, не показывается в v0:** превью-плеер
  (C2) — конвенция файла, сигнала «нажали ▶» в контракте нет. Поле схемы
  заполняется нулём; когда появится сигнал (кандидат — вместе с C4/cancel
  в v1), панель покажет «прослушиваний» в ленте версий. Явно указано,
  чтобы Фронтендер не выдумывал источник данных.
- **PRD-связка:** панель = UI-инструментация метрики PRD §4; авто-прокси
  показываются рядом с решениями человека, чтобы будущий анализ
  «какие паттерны принимают» имел сырьё. Survival-check («слой жив в
  DAW через N сессий») — opt-in, v1 (§5.3 proposal), в панель не входит.

## 5. Маппинг на ipc-contract v0.2 — предложение C7

**Зазор:** данных панели в контракте нет; UI не читает файловую систему
сам (UI = проекция шины, FS принадлежит ядру).

**Предложение C7 — команда `get_acceptance_stats`:**

| | |
|---|---|
| Вход | `{}` |
| Выход | `AcceptanceStats`: `overall {accepted, total, rate}` · `per_part {part → {accepted, total, rate, versions[] {version, decision, params, ts}, proxies}}` · `by_mode {manual, agent, autopilot}` · `first_decision_ts?` · `manifest_ok: bool` |
| Когда вызывать | открытие вкладки; после локального accept/reject |
| События | не нужны (§3) |
| Включение в ядре | обогащение manifest-записей до схемы §5.3 (params/source_tool/mode + прокси при записи) |

**Фич-флаг (паттерн ui-screens §7):** вкладка [Статистика] и мини-бейджи
рендерятся **disabled** с тултипом «C7 — ждёт согласования контракта» до
вердикта Папы; после вердикта — один флаг включает вкладку. Спека
разрабатывается как написана, включение = переключение флага. Без C7
данных у панели нет альтернативного пути (и не должно — см. зазор выше).

**Что НЕ добавляем в контракт:** события stats_updated (сталeness
задокументирована — §3), reset-команда (сброс = удаление staging/
руками, сознательно без кнопки — защита от случайной потери данных),
экспорт-команда ([Скопировать сводку] — локальный clipboard UI-слоя).

## 6. UX-тексты (готовые к вставке)

- Empty: «Пока нет решений. Сгенерируй партии в Channel Rack — после
  первого ✓/✕ здесь появится статистика.»
- Малая выборка: «Метрика осмысленна от ~10 решений — пока это просто
  история решений.»
- Приватность (всегда видна внизу панели): «🔒 Всё локально: считается
  из manifest.json в папке твоего проекта. Без облака, без телеметрии,
  без отправки данных.»
- Tooltip приватности: «manifest.json лежит в <workspace>/staging/.
  Удалишь файл — статистика начнётся с нуля.»
- Error: «Статистика недоступна: manifest.json повреждён. Файл:
  <путь>. Остальные панели работают.»
- Общая фраза (шаблон): «Ты оставляешь {n} из {m} предложений ИИ» —
  падежи: 1 решение / 2,3,4 решения / 5–10 решений (ru-склонение —
  учесть; в буфер копируется JSON-сводка, там просто числа).

## 7. Свобода Фронтендера (не спрашивать)

- Визуал ленты версий (точки/квадратики), плотность строк, точный вид
  полосы overall — его выбор в рамках словаря выше.
- Способ склонения ru-фразы и формат tooltip'ов.
- Кеширование последнего ответа C7 в памяти вкладки (перепоказ мгновенный,
  refresh по триггерам §3) — допустимо; источник истины — ответ ядра.
