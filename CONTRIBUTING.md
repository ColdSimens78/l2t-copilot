# Contributing to L2T Copilot

Спасибо за интерес к проекту! L2T разрабатывается мультиагентной командой
(мейнтейнер проекта) и открыта для человеческих и агентных
контрибьюторов. Этот документ — как влиться без боли.

## Языки проекта

- Код: Rust (ядро и кокпит), Python (MCP-серверы), TypeScript/React (UI)
- Документация и коммуникации: русский

## Быстрый старт разработки

Полное окружение: [`docs/frontend-env-setup.md`](docs/frontend-env-setup.md).
Коротко:

```bash
# Python (MCP-серверы + тесты)
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest tests/

# Rust (ядро l2t-core + кокпит)
. ~/.cargo/env && cargo test -p l2t-core

# UI (Tauri + React)
cd ui && pnpm install && pnpm dev --port 5199
```

## Контракт шины — читайте первым

[`README.md` § «Контракт шины»](README.md#контракт-шины-7-правил--выжаты-из-реальных-инцидентов)
и [`docs/ipc-contract.md`](docs/ipc-contract.md) — **единый источник типов
фронт↔ядро**. Все 7 правил обязательны (workspace-песочница, таймаут ≠ отказ,
bounded-ошибки, сессия — источник истины и т.д.). Нарушение контракта =
баг на ревью, каким бы красивым ни был код.

## Правила коммитов (выработаны на инцидентах)

1. **Никогда `git add -A` / `add .`** — только явные пути ваших файлов
   (правило №6: одно время чужой недописанный документ улетел в публичный
   коммит).
2. **Conventional Commits**: `feat:` / `fix:` / `docs:` / `test:` / `ci:`.
3. Один логический смысл = один коммит. Тесты — в том же коммите.
4. Push в `main` — только из ветки с пройденным CI (`ci.yml`: pytest +
   cargo test). Коммиты мимо CI = отклоняются ревью.

## Изменения IPC-контракта (фронт ↔ ядро)

Схема в [`docs/ipc-contract.md`](docs/ipc-contract.md) версионируется:

1. Предложение изменения (issue или PR) с обоснованием.
2. Bump версии контракта в том же PR.
3. **Обе стороны обновляются вместе**: Rust (`crates/l2t-core/src/contract.rs`)
   + TS (`ui/src/types/`) — никто не остаётся на старой схеме.
4. Формат нот — только `core/midi_io` (`{note, start, end, velocity, channel}`).

## Тесты обязательны

- Python: pytest, `MockTransport`/monkeypatch вместо живых серверов.
- Rust: cargo test; интеграционные — с явным skip, если зависимости
  (binary/soundfont) отсутствуют.
- Детерминизм: генерация не должна использовать randomness (проверяемо
  байт-в-байт).

## Документация

- Новые спеки/разведки/отчёты — в `docs/`, русский язык, стиль существующих
  файлов (таблицы, светофор лицензий, «рекомендация берём»).
- Лицензии зависимостей проверяйте **по содержимому LICENSE-файла**, не по
  бейджам. GPL/AGPL — не копируем в репо (только внешние процессы);
  правило и полный манифест — [`DEPENDENCIES.md`](DEPENDENCIES.md).

## Архитектурные решения

Крупные развороты (движок, хосты, формат) — через [`DECISION.md`](DECISION.md)
с триггерами и процедурой. Идеи — issue с меткой `enhancement`; обсуждаются
открыто, решение — мейнтейнер.

## Стиль общения

По делу и без выпячивания: документируйте факты (числа, замеры, логи),
интерпретируйте честно (низкая confidence помечается), предлагайте —
решают владельцы.
